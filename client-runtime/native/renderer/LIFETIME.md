# Metal interop leases

The optional lease ABI is version 1. Each scene permits one device lease and one current-frame target lease. The 48-byte information record contains the committed frame ID, target generation, dimensions and borrowed Metal object addresses. Acquisition and access require the scene's native owner thread. Failure clears output handles/information.

The device lease retains the scene, device and queue across frames. A target lease additionally retains the exact color texture and checks its committed frame/generation. Open or retiring targets prevent ordinary scene mutation. An explicit `arc_scene_wait` returns busy while a target is open; after release it waits for queued retirement with the same bounded five-second deadline.

External drawing must use the provided command queue. After Skiko submits its work, close Surface/BRT children, then release the target. Release appends a completion marker on that same queue and retains the objects until it completes; it performs no CPU wait. Apple documents ordered command-buffer execution and completion handlers in [Command Organization and Execution Model](https://developer.apple.com/library/archive/documentation/Miscellaneous/Conceptual/MetalProgrammingGuide/Cmd-Submiss/Cmd-Submiss.html). Other queues require a separate synchronization contract.

`MetalDeviceLease` passes addresses only into owner-checked resource factories and adopts their returned `AutoCloseable` resources. It owns at most eight children per device/frame scope. Children close in reverse order before native handles retire. Duplicate ownership, stale frames, reentrant cleanup and cross-thread calls are rejected. A failed close keeps the handle and remaining children reachable for retry and blocks new scene work. Backend close retires these scopes before closing presentation/context ownership.

Queries 10/11 return device/target states (0 absent, 1 open, 2 retiring); query 12 returns target generation. Native tests cover same-queue external writes and lifetime guards. A separate probe uses the actual shipped Skiko 0.154.0 API/native JARs and the existing Poppins font to create Metal DirectContext/BRT/Surface objects, render rectangles/text/blur across three sizes, and perform diagnostic readbacks after retirement. It does not select a Minecraft UI backend or qualify world rendering, presentation, minimum-version hardware or performance.
